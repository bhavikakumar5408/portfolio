Summary

Brewmac is an automated beverage-dispensing system — drinks are configured on a dashboard and poured by a machine.

  • Running it well means understanding how liquids, valves, recipes, and events all connect

  • The existing dashboard never made those connections visible to the people operating it

  • A heuristic evaluation surfaced 14 critical friction points across the system

I redesigned two core experiences around those findings:

  • An analytics page rebuilt to support decisions instead of burying them in data

  • A guided setup flow that replaces trial-and-error recipe configuration with clear, step-by-step progress


The Problem

The dashboard wasn't just hard to use — its inconsistencies were causing real failures nobody could immediately explain.

The story that revealed it:

  • An operator listed a liquid as "lime juice" under Liquids

  • The corresponding valve was named "lemon juice" under Valves

  • Because the names didn't match, the system couldn't link the valve during recipe setup

  • Drinks needing that liquid simply stopped pouring

  • Users assumed it was a hardware failure and contacted customer support

  • My manager traced it back through user conversations — the real cause was a naming inconsistency in the dashboard, not the machine

A UX problem was hiding as a mechanical one, and it cost real support time before anyone caught it.

Other problems uncovered:

  • Operators didn't know where to start when configuring a recipe, and routinely missed steps

  • Managers opened the analytics page looking for a decision and got a wall of unprioritized data instead

  • New users depended on more experienced staff just to complete basic tasks.

Who Are We Solving For?

Operators (Setup Staff) — hands-on, task-focused

  • Tasks: add liquids, configure valves, build recipes and recipe profiles

  • Behavior: uses the dashboard mainly during setup, follows it step-by-step, depends heavily on it for guidance

  • Pain points: doesn't know where to start · misses steps · naming/duplication errors cause operational failure

Managers (Business Users) — occasional, outcome-focused

  • Tasks: track sales, review event performance, analyze trends

  • Behavior: uses the dashboard occasionally, wants a quick takeaway, not deep exploration

  • Pain points: too much data, no clear takeaway · hard to know what needs attention · feels like reporting, not deciding

System Flow: Recipe Configuration

Add Liquids → Configure Valves → Add Recipes → Add Recipe Profiles → Add Events/Venue → Save

Six steps, entirely sequential — but nothing in the interface communicated that sequence to the person using it.

Heuristic Evaluation

[Fig 1.0 — annotated interface mapping]
Initial interface mapping identifying 14 critical friction points

Four root causes:

  • Unclear workflow — the system follows a sequence, but it isn't communicated; users don't know what comes next

  • High cognitive load — information isn't structured or prioritized; users must interpret before they can act

  • Inconsistent interactions — the same liquid could be named differently across screens with no validation catching it (this is how lime juice/lemon juice became a "broken hardware" ticket)

  • Lack of guidance — no onboarding, no contextual support; users rely on trial and error

Design Objectives

Primary goal: enable users to complete tasks independently, with clarity.
Target impact: fewer errors, faster task completion.

Two directions:

  1. Clear, actionable Report Insights page — structure information so key data is easy to understand and act on

  2. Guided onboarding for complex setup — step-by-step support for clarity and fewer errors

Design Direction 1: Report Insights

Goal: restructure analytics to surface what matters and reduce cognitive load
Key decisions: prioritized important metrics · reduced unnecessary data · improved hierarchy and grouping

Step 1 — Understanding the current state
How is the analytics page actually being used?

  • Gathered stakeholder input on the page's real purpose, actual usage, and relevance of existing data

Step 2 — Identifying gaps
What's working and what's not?

  • Lack of clarity — users struggled to understand key metrics and how they related

  • Information overload — too much data, no prioritization

  • Low actionable value — insights didn't guide decisions

  • Underutilized sections — some data blocks rarely used

  • Inconsistent hierarchy — important info didn't stand out

Step 3 — Mapping opportunities

  • Converted stakeholder feedback into a prioritized feature map

  • Sorted by: core purpose (venue performance, machine health, remote ops) · high-priority · low-priority · future expansion

Design Direction 2: Guided Setup for Complex Tasks

Goal: support users through complex, multi-step workflows like recipe configuration — the exact workflow where the lime juice/lemon juice failure happened

Key decisions:

  • Step-by-step progression instead of a single dense form

  • Contextual guidance delivered at the moment a user needs it

  • Clear feedback at each step, so a naming mismatch or missed step is caught immediately — not later, as a failed pour and a misdirected support ticket
